# M1.11 — Register SC-005 and SC-008

Adds the two PARTIALLY_BLOCKED acceptance scenarios to `fixtures/scenario-pack-v1`
and moves the dataset to **`1.5.0`**. Requirements, harness contracts, schemas,
safety policies, model profiles (release `m1-saturday-runtime-0.6`) and limits are
unchanged.

Following harness design SH-OD-008, each is an ACTIVE container. Its runnable
synthetic assertions are mandatory, and the spec's unresolved real-world
classification is an explicit optional BLOCKED atomic assertion. A full PASS
therefore means "the declared policy result is enforced". It does not mean the
real-world classification is established.

## SC-005

"Where should I paddleboard tomorrow morning?" B and D are the SUP-supported
candidates.

**Inputs.** B's `DANGEROUS_OFFSHORE_WIND_PRESENT` premise is declared **true**,
supported by the regional wind finding, so HM-WIND-002 fails for SUP. D keeps
complete non-hazard premises.

**Assertions.** They require:

- B EXCLUDED and UNFAVORABLE, with HM-WIND-002 in its disqualifying policies, a
  `CANDIDATE_EXCLUDED` event, and B not recommended.
- The wind finding still REGIONAL with its coverage ID, so source geographic
  coverage is preserved.
- D eligible and the only recommendation.
- A, C and E not recommended, since they do not support SUP.

**Blocked.** The spec's blocked assertion is an optional BLOCKED row: whether wind
measurements and shoreline orientation actually produce the disqualifying result
needs approved wind-hazard criteria.

**Not exercised.** "Geographic preferences cannot override the policy" is not
exercised, because the spec's request names no area. The SC-004 and SC-011
exclusions show the same precedence with an area in the request.

## SC-008

"Where should I snorkel tomorrow morning near Kihei?"

**Inputs.**

- The regional NWS marine option is scoped to **surf only**.
- A local Snorkel Store report (`LOCAL_CURRENTS_A`, BEACH coverage for A) is the
  **only** currents source.
- A `MATERIAL_SAFETY_CONFLICT_PRESENT` premise is declared true for A, naming both
  findings.
- A's current-hazard and positive-support facts are omitted, because the conflict
  leaves them undetermined.
- B, C and D are undeclared, so the run abstains, matching the spec's
  NO_RECOMMENDATION case.

**Forced retrieval.** M1.10 showed a live model skips redundant optional sources.
Making the local report the only way to cover a required category means the
conflicting evidence is actually retrieved.

**Assertions.** They require:

- Both findings retrieved and **LIMITED**, neither rejected nor averaged.
- Marine still REGIONAL and the local report BEACH, so regional evidence is not
  relabeled as beach-specific.
- `EVIDENCE_CONFLICT_DETECTED`.
- A NEEDS_INVESTIGATION / UNDETERMINED / LIMITED, with ES-009 unresolved, non-empty
  conflicting findings and no disqualifying policy. A conflict is not a hazard
  verdict.
- `INVESTIGATION_ABSTAINED`, no recommendations, an explanation, and a
  no-recommendation reason other than `APPLICABLE_HAZARDS`.

Requirements covered: EF-008, CA-009, ES-V010 and CF-006.

**Blocked.** "Automatic conflict classification requires final measurement and
materiality rules" is an optional BLOCKED row. Materiality is declared, never
computed.

### Owner decisions

1. **Split `MODEL_PLAN_NOT_ALLOWED`.** This is its second occurrence (after SC-007
   #2) on an allowlist without duplicate `VISIBILITY_` options, so the rename
   theory does not explain it. The specialist-plan check now raises one closed code
   per condition:
   - `MODEL_PLAN_OPTION_NOT_ALLOWED`: an invented option ID.
   - `MODEL_PLAN_GAP_NOT_ALLOWED`: declared `unresolved_gap_ids`, which must be a
     subset of the always-empty `gap_ids`.
   - `MODEL_PLAN_TOO_LONG`: more steps than remaining tool calls.

   All three join the gateway's closed `ERROR_CODES`. `MODEL_PLAN_NOT_ALLOWED`
   remains in the vocabulary for the Coordinator delegation budget check and for
   earlier traces. All 39 existing traces still validate.
2. **Rename SC-008's options to match their roles.** The Ocean prompt says
   "MARINE_ covers surf plus currents", and option names are the model's only signal
   of coverage, so a surf-only `MARINE_ABCD` was read as covering currents. The
   options are now `REGIONAL_SURF_ABCD` and `LOCAL_CURRENTS_A`. Neither uses the
   `MARINE_`/`SURF_`/`CURRENTS_`/`RETRY_` conventions, so both read as plain
   originals.
